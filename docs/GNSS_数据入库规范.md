
# GNSS数据管理系统——数据入库规范

版本：V1.0  
制定日期：2026-10-21  
适用系统：GNSS Data Management System

---

## 1. 建设目标

本规范用于统一GNSS观测数据的接收、检查、
存储、索引、查询及下载管理流程。

主要目标：

1. 统一GNSS站点信息格式。
2. 统一RINEX观测文件管理方式。
3. 实现文件元数据自动提取。
4. 建立数据完整性检查机制。
5. 为后续MySQL数据库建设提供依据。
6. 支持GNSS原始数据与处理成果分类管理。

## 2. 数据分类

系统管理的数据分为以下三类。

### 2.1 GNSS站点信息

包括：

- 站点编号
- 站点名称
- 纬度
- 经度
- 站点状态

后续扩展：

- 站点高程
- 坐标参考框架与参考历元
- 接收机型号
- 天线型号
- 建站时间
- 站点所属单位

### 2.2 GNSS原始观测数据

包括：

- RINEX观测文件
- RINEX导航文件
- 压缩RINEX文件

支持的具体版本和压缩格式，
以入库程序实际检测能力为准。

### 2.3 GNSS处理成果

包括：

- GNSS解算结果
- 站点坐标成果
- 时间序列数据
- 质量评估报告

处理成果与原始数据分开保存。

## 3. 数据存储目录

建议采用以下结构：

GNSS_DATA/
  raw/
    站点编号/
      年份/
        年积日/
  processed/
    站点编号/
  quarantine/
  logs/
  metadata/

目录说明：

raw：原始GNSS数据。

processed：GNSS处理成果。

quarantine：待检查或未通过校验的数据。

logs：文件入库日志。

metadata：元数据备份。

原始文件原则上保留原始名称，
不得随意覆盖或修改。

## 4. GNSS站点信息规范

当前使用：

data/stations.csv

字段：

station_code
station_name
latitude
longitude
status

字段要求：

1. station_code必须唯一且非空。
2. 站点编号统一使用大写字母。
3. latitude使用十进制度，范围-90至90。
4. longitude使用十进制度，范围-180至180。
5. status采用统一的状态编码。

建议状态：

active：正常运行。

inactive：停止运行。

unknown：状态未知。

后续正式入库时，
应明确站点坐标参考框架和参考历元。

## 5. RINEX文件索引规范

当前使用：

data/rinex_files.csv

字段：

file_id
station_code
filename
observation_date
file_type
file_size
storage_path

字段要求：

1. file_id为唯一文件标识。
2. station_code关联GNSS站点。
3. filename保存原始文件名称。
4. observation_date采用YYYY-MM-DD格式。
5. file_type采用统一分类编码。
6. file_size以字节为单位。
7. storage_path记录文件相对路径或存储键。

建议文件类型：

OBS：观测文件。

NAV：导航文件。

OTHER：其他已识别文件。

对于跨日或非单日文件，
应增加start_time和end_time，
记录实际观测时间范围。

## 6. GNSS数据入库流程

### 6.1 文件接收

记录：

- 文件来源
- 原始文件名
- 接收时间
- 文件大小

文件先进入待入库区域。

### 6.2 文件格式识别

检查：

- 文件扩展名
- 文件压缩格式
- RINEX版本
- 文件头信息

不能仅依靠扩展名判断文件有效性。

### 6.3 元数据提取

优先从RINEX文件头提取：

- 站点标识
- RINEX版本
- 文件类型
- 观测时间信息

同时结合文件名进行交叉检查。

### 6.4 数据校验

检查内容：

1. 文件是否能够正常读取。
2. 文件是否完整。
3. 站点编号是否一致。
4. 观测时间是否合理。
5. 文件是否重复。
6. 文件大小是否异常。

使用SHA-256生成文件校验值。

无法确定的信息标记为待人工复核。

### 6.5 文件归档

校验通过后，按以下规则归档：

raw/站点编号/年份/年积日/

不得直接覆盖已有原始文件。

校验失败的文件进入quarantine目录，
并记录失败原因。

### 6.6 文件索引登记

登记：

- 文件唯一ID
- 所属站点
- 文件名称
- 观测日期
- 文件类型
- 文件大小
- 存储位置

后续扩展：

- RINEX版本
- 开始与结束观测时间
- SHA-256校验值
- 数据来源
- 入库时间
- 质量检查状态

### 6.7 查询与下载

通过Streamlit网页读取文件索引。

支持按站点、观测日期和文件类型查询。

实际文件下载需连接正式存储服务，
并根据用户权限提供访问。

## 7. 入库状态管理

建议设置以下状态：

pending：等待检查。

passed：检查通过。

failed：检查失败。

manual_review：需要人工复核。

文件入库校验与GNSS观测质量评价
属于不同的工作阶段。

## 8. 数据安全管理

1. 原始GNSS文件不得随意删除。
2. 文件入库应保留日志。
3. 重要数据应定期备份。
4. 文件索引与原始文件保持一致。
5. 不在公开GitHub仓库存放敏感数据。
6. 不在代码中保存数据库密码。
7. 正式系统应设置用户身份认证与权限。
8. 大型RINEX文件应使用独立存储服务。
